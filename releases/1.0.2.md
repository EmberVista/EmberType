# EmberType 1.0.2 (build 206) — Release Log

Written step by step as the release happens so it can be audited or repeated.

**Why:** two paying customers (2026-09-23/24) couldn't find or manage their license key.
The in-app "Manage License" button opened `https://polar.sh/purchases`, which returns 404.
The correct customer page is `https://polar.sh/embervista/portal` (email + one-time code).

**Scope:** that one URL + version bump. Nothing else changes, to keep the risk low for existing users.

- Certificate `Developer ID Application: Steve Mount (2574M8R98B)` in the login Keychain (same one that signed 1.0.1).
- Sparkle EdDSA private key in Keychain verified: re-signing the live 1.0.1 DMG reproduced the live appcast signature exactly.
- Live 1.0.1 DMG inspected: v1.0.1/205, SUFeedURL `https://embertype.com/appcast.xml`, SUPublicEDKey `YfdC4fsY…Te9E=`, stapled.
- `Secrets.swift` present and populated (gitignored, never committed).

## Steps
1. Committed the uncommitted 1.0.1 source as shipped (`0734504`) and tagged it `v1.0.1`.
2. Changed `Views/LicenseManagementView.swift` Manage License URL → `https://polar.sh/embervista/portal`; version 1.0.1/205 → 1.0.2/206; CHANGELOG updated.
3. **Archive**: `xcodebuild -project VoiceInk.xcodeproj -scheme EmberType -configuration Release -archivePath ~/EmberType-Releases/1.0.2/EmberType-1.0.2.xcarchive archive` → ARCHIVE SUCCEEDED, Info.plist 1.0.2 / 206.
   - Note: the scheme is `EmberType` (not `VoiceInk`).
   - Note: the untracked folder `VoiceInk/EmberTalk 1.0.0/EmberType.app` sits inside a synchronized group, so Xcode copies a stale 1.0.0 app into `Contents/Resources/`. 1.0.1 shipped with it too. Left unchanged here so 1.0.2 matches 1.0.1's structure; **follow-up: remove it in a later release.**
4. **Export (Developer ID)**: `xcodebuild -exportArchive … -exportOptionsPlist ExportOptions.plist` with `method=developer-id`, `teamID=2574M8R98B`, `signingStyle=automatic`, `destination=export`.
   - `signingStyle=manual` fails: the Developer ID profile `09272b0a-…` ("Mac Team Direct Provisioning Profile", expires 2044) is Xcode-managed. Automatic picks the same profile.
   - The profile is required: the `keychain-access-groups` entitlement (where licenses are stored) needs it.
5. **Signing parity check vs shipped 1.0.1** (the extracted live DMG is kept at `~/EmberType-Releases/1.0.1-shipped/`):
   - Removed the broken `whisper.framework/Info.plist` symlinks (outer + nested app) and re-signed inside-out with `--timestamp` and `--preserve-metadata=identifier,entitlements,requirements,flags,runtime` (no `--deep`).
   - `codesign -vvv --deep --strict`: valid on disk, satisfies its Designated Requirement.
   - **8/8 components identical to 1.0.1** in certificate, team, runtime flag, entitlements and designated requirement (main app, nested app, Sparkle.framework, Updater.app, Downloader.xpc, Installer.xpc, whisper, MediaRemoteAdapter). Existing Keychain licenses and TCC permissions carry over.
   - File tree identical to 1.0.1, except 1.0.1 had a stray top-level `Contents/CodeResources` (a leftover from its re-signing; harmless).
6. **Notarize app**: `ditto -c -k --keepParent` → `xcrun notarytool submit --keychain-profile AC_PASSWORD --wait` → submission `766158e1-5afa-47f8-81fc-eed44d4946cc` **Accepted, 0 issues** → `stapler staple` → `spctl`: accepted, "Notarized Developer ID".
7. **DMG**: staging folder = signed app + `/Applications` symlink + `.DS_Store` copied from the shipped 1.0.1 DMG (same window layout) → `hdiutil create -volname EmberType -fs HFS+ -format UDZO` (matches 1.0.1: UDZO, HFS+, volume "EmberType") → codesigned with Developer ID → notarized separately, submission `048365ca-1288-4f3b-9ffa-fa6c5079a6c4` **Accepted** → stapled → `spctl --type open`: accepted.
   - Final `EmberType.dmg`: 14,789,422 bytes, SHA-256 `6429767800e8284da009556d7260382cd41d7ff2c4387877680cc3a875db5077`.
   - Sparkle EdDSA: `9B37fbnbyUyNiV3daBfXf+E/iVLju9oldIunP8Z0vGcRzCVxDD5hIuYjuiImd9q4A7aIXRNBs8j9oHrEkaHlCQ==`.
   - `sign_update` path on this Mac: `~/Library/Developer/Xcode/DerivedData/VoiceInk-dcslmwgnfehonnepcbkihsknsffd/SourcePackages/artifacts/sparkle/Sparkle/bin/sign_update` (the DerivedData path in the website CLAUDE.md is stale).
